# v2.1 - WAL Recovery & Segment Architecture

v2.1 introduces immutable index segments, deterministic compaction, and WAL replay on startup.

## Write path

1. Append the mutation to the WAL and fsync.
2. Apply it to the in-memory index and metadata store.
3. Persist an immutable segment.
4. Checkpoint the WAL after the segment is durable.

## Recovery

On startup, the engine loads the latest segment view and replays any complete pending WAL records. A malformed/truncated final WAL record is ignored, preventing a partial tail write from corrupting recovery.

## Segments

Each indexing batch becomes an immutable JSON segment. The manifest records segment order. When multiple segments accumulate, compaction materialises the latest document version for each document ID into a single segment and removes superseded segments.

This is intentionally a transparent reference implementation: the segment format is inspectable and deterministic, making the storage lifecycle suitable for systems-programming experiments and interview discussion.
