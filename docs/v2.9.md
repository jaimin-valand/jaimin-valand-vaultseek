# v2.9 - Search Observability & Distributed Tracing

## Goals
- correlate a distributed query with one trace ID
- measure fan-out, shard retrieval, and result-merge latency
- classify failed spans
- retain bounded in-process telemetry
- expose deterministic metrics for benchmarking

## Trace model
A `SearchTrace` contains a trace ID and ordered span events. Each event records a stage name, parent span, duration, status, and bounded attributes.

## Privacy boundary
Telemetry does not store document bodies, credentials, or full result payloads. Query text is retained in the in-memory trace attributes for local debugging; production deployments should disable or redact it when query confidentiality requires it.

## Metrics
- trace count
- error count
- average latency
- P95 latency
- per-stage invocation counts
- per-stage total/max duration

## Distributed stages
`query.fanout` -> `shard.search` (one span per node) -> `result.merge` -> root `query`.
