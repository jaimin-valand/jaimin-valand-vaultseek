# v2.5 - Query Consistency & Distributed Transactions

v2.5 adds a deterministic quorum-consistency layer on top of the replicated search architecture.

## Guarantees

- Majority-style read and write quorums are configurable.
- Every document mutation receives a monotonically increasing per-document version.
- Reads select the highest observed version from the read quorum.
- Stale replicas can be repaired during reads.
- Failed nodes do not acknowledge writes or participate in quorum reads.
- Writes explicitly report whether the acknowledgement quorum was reached.
- The layer is local-first and deterministic for reproducible tests; it does not claim to be a full consensus protocol such as Raft.

## Failure model

With three replicas, the default configuration is `R=2, W=2`. This means `R+W>N`, so a successful quorum read and write overlap on at least one replica. The implementation deliberately avoids claiming linearizability or consensus: network partitions and concurrent writers require a consensus protocol in a future generation.
