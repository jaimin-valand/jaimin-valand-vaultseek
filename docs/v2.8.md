# v2.8 - Consensus Snapshots & Log Compaction

The consensus layer now supports durable snapshots and safe log compaction.

## Snapshot model

A snapshot records the state needed to recover through a committed index:

- current term
- last included log index
- last included log term
- commit index
- materialized key/value state
- SHA-256 checksum

Snapshots are written to a temporary file and atomically replaced into place. Loading verifies the checksum before accepting the state.

## Compaction invariant

Only entries at or below the snapshot's `last_included_index` are removed. Entries after that boundary remain available for replay. This prevents compaction from deleting an uncommitted tail.

## Recovery model

```text
Snapshot
  +
Log tail after snapshot index
  ↓
Recover state
  ↓
Replay remaining entries
```

This is still an educational/in-process Raft-style implementation rather than a claim of production-grade Raft. A production implementation would additionally need formal snapshot installation semantics, membership changes, durable fsync policy, network transport, and extensive crash testing.
