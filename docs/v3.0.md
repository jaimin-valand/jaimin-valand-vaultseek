# v3.0 Production Search Platform

v3.0 consolidates the crawler, retrieval, distributed search, persistence, replication, consensus and observability layers behind a production-style service boundary.

## Production controls

- Environment-driven configuration (`PSE_*` variables)
- Optional constant-time API-key authentication
- Per-client sliding-window rate limiting
- Request IDs and processing-time headers
- Request body size limits
- Remote-node count limits
- `/health`, `/ready`, and `/version`
- Graceful shutdown/draining state
- Load-test utility with average/P95/max latency
- Release gate combining the complete test suite and Python compilation

## Security boundary

Authentication is disabled when `PSE_API_KEY` is empty, which keeps local development frictionless. Production deployments should set a strong secret through the environment/secret manager. The service never logs API keys. Rate limiting is process-local; production multi-instance deployments should place a shared gateway or distributed limiter in front of the application.

## Load testing

```bash
python -m private_search_engine.cli load-test http://127.0.0.1:8000/search --requests 100 --concurrency 10 --query python
```

## Release gate

```bash
python -m private_search_engine.cli release-gate
```

The gate runs `pytest -q` and `compileall`. Docker builds are intentionally not claimed unless Docker is actually available in the execution environment.
